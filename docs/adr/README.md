# Rejestr decyzji architektonicznych (ADR)

ADR opisują ważne wybory w architekturze danych, bezpieczeństwie, integracjach i reproducibility. **Nie zastępują** decyzji naukowych dotyczących hipotez, metodologii i analiz z [research/decisions.md](../../research/decisions.md).

| ID | Temat | Status |
| --- | --- | --- |
| [0001](0001-research-data-boundaries.md) | Oddzielenie danych prywatnych od publikacji | proposed |

Każdy ADR powinien zawierać datę, status `proposed/accepted/rejected/superseded`, kontekst, rozważane alternatywy, decyzję, konsekwencje i źródła dowodów. `proposed` nie jest zgodą na wdrożenie. Nowy ADR zastępujący wcześniejszy podaje odnośnik i uzasadnienie, a wcześniejszy zmienia status na `superseded`.

Następny ADR twórz tylko wtedy, gdy istotna decyzja nie należy do protokołu lub SAP i nie jest już zapisana w istniejącym ADR. Przestrzegaj [limitu znaków](../documentation.md).
